**What ships in v2.0.43**

| # | Change | User-visible |
|---|--------|--------------|
| 1 | **"Sign in again" instead of "Voiceprint required" when the Microsoft sign-in is lost.** If the central voiceprint check can't run and the main process reports no usable Microsoft account (token cache missing/undecryptable, or refresh token expired/revoked), the gate shows **Sign in again** at once (no ~50 s retry spin). Its button runs the real Microsoft sign-in, then re-checks; no re-enrolment. | **Yes**: the FD-2265 fix |
| 2 | **"Couldn’t check your voiceprint"** with **Try again** when signed in but the central store is unreachable. Never claims the user is signed out. | **Yes** |
| 3 | **"Voiceprint required"** only for a user the central store confirmed has no voiceprint. Loading reads **Checking your voiceprint**. | **Yes** |
| 4 | **Cold start trusts the Microsoft sign-in, not the cached name.** A stale `mn.user` in local storage no longer outlives a cleared token cache: no usable account → login screen. | Yes, only for affected users |
| 5 | Main process: "signed in" = a usable MSAL account (in memory or a decryptable cache) not disproved by the last Storage API token attempt. The renderer-pushed audit display name never counts, and **an empty display name no longer deletes the token cache**; only **Sign out** does. | No |
| 5b | **After "Sign in again", main checks the voiceprint store will issue a token** (review R-1, option b). If it still refuses (e.g. a policy on that resource), the gate keeps the session and says "You’re signed in, but Notetaker still can’t reach the voiceprint service. Contact the IT service desk." instead of silently re-showing the button. The login screen and email retry ignore the new `storageAccess` field. | Only in that edge case |
| 5c | **Sign out always wins over an in-flight sign-in** (review R-3, option c), from the gate, the email retry, or the app menu:<br>• Sign-out releases a sign-in still waiting on the browser at once (previously it waited up to 2 minutes) and closes the loopback listener.<br>• A browser sign-in that completes after sign-out is undone (cache cleared again).<br>• A sign-out during the post-sign-in Storage check also wins.<br>• The gate ignores a sign-in result that lands after Sign out.<br>Side effect: an email retry interrupted by sign-out reports "Signed out during sign-in". | Rarely: only when signing out mid-sign-in |
| 6 | CI runs two new checks: `verify:sign-in-gate` (pure logic + screen copy) and `verify:fd2265-auth-ipc` (built renderer/preload + real main auth IPC, synthetic). | No |

Backend: unchanged. Untouched: fail-closed gating, the encrypted (DPAPI) cache codec, enrolment semantics.

### 1.1 Independent review

Independent agent review of the full uncommitted diff, read-only, 16 Nov. **Verdict: nearly merge-ready; no critical bugs.** It confirmed:
- the audit actor is no longer a sign-in and no longer deletes the cache;
- the cold-start check also closes an older bug, where `setUser('')` on mount wiped a healthy cache when `mn.user` was absent;
- healthy restarts, `--background` auto-record, the EnrollmentModal preflight, `retryTranscriptEmail`, StrictMode and cancellation show no regressions.

Findings, each re-checked against the code:

| # | Finding | Verified | Disposition |
|---|---|---|---|
| R-1 | **"Sign in again" can loop** when the Storage API scope itself returns `interaction_required` (missing consent, resource-specific Conditional Access). Interactive sign-in requests only the Graph scopes (`SIGN_IN_SCOPES`, auth-msal.ts:28). The main-side `call-signals` poller also calls `getStorageApiAccessToken`, so a persistent failure could also send the user to the login screen on restart. Before this change, the same user saw retry wording that never cleared. | Yes, premises confirmed. Entra check (16 Nov, read-only): `Notetaker Storage API`/`access_as_user` has tenant-wide admin consent (`AllPrincipals`), so the realistic trigger is a resource-specific Conditional Access policy (not readable with this token) or revoked consent | **Fixed with option (b), approved by Joseph 16 Nov** (row 5b). Residual: if such a policy exists, a restart can still land on the login screen. The user now gets an explanation instead of a silent loop. |
| R-2 | The harness did not exercise the real "Storage `no_cached_account` → `auth:status` false" chain. | Yes | **Fixed (test only):** Part 1 now drives the real `getStorageApiAccessToken` with fake IDs and an empty MSAL cache (no network); 2 checks + 2 mutations. |
| R-3 | **Sign out** stays enabled while "Sign in again" is in flight. Signing out mid-flow, then finishing the browser sign-in, signs the user back in. | Yes. The same race also existed before this change for the email-retry sign-in plus the app-menu Sign out; main's sign-out never cancelled the 2-minute browser wait | **Fixed with option (c), approved by Joseph 16 Nov** (row 5c). Sign out stays available as the way out of an abandoned browser sign-in. The loopback-listener close is best effort; correctness relies on the late-completion undo. |
| R-4 | If `/people/me` succeeds but the status call fails for the whole backoff, the existing Slice 1 null-status fallback can still show "Voiceprint required" + wizard. | Yes; unchanged pre-existing path | Documented; not a regression. |
| R-5 | A sign-in result with no email shows "did not complete". | Yes; same as `LoginScreen` and `retryTranscriptEmail` | No change. |
