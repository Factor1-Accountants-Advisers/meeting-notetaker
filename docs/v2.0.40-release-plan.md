# v2.0.40 — Release plan

Prepared 22 Sep 2026. Cut: pending (see §2; the signing credential has to
be re-created first).

**What ships in v2.0.40** (branch `feature/invitee-email-prompt`, merged as
`47611bc`; 14 plan tasks + one final fix wave + one whole-branch review;
spec `docs/superpowers/specs/2026-09-21-in488-invitee-prompt-design.md`,
plan `docs/superpowers/plans/2026-09-21-in488-invitee-prompt.md`):

| # | Change | User-visible |
|---|--------|--------------|
| 1 | **Ask before emailing invitees (IN-488).** When a meeting's notes are ready, nothing is saved to SharePoint or emailed until the recording owner answers **Email invitees** / **Just me**, as a Windows toast and as a Home card at the same time. No answer in 2 minutes = Just me. A "Just me" meeting keeps a **Send to N invitees** button; that later send goes to the invitees only, never to the owner twice. Ad-hoc recordings prompt too (the attendee-picker selections are the invitees). External addresses never appear (domain allowlist, as before). | **Yes** — the headline change; DA's IN-488 |
| 2 | **Delivery mode** `MN_DELIVERY_RECIPIENTS`: `ask` (new code default) / `organizer` (kill switch: never prompt, owner only, blocks even a stored approval) / `attendees` (auto-approve, no prompt). Anything else reads as `organizer`. | Only if flipped |
| 3 | **Restart recovery.** Unanswered meetings, owner-only meetings, and meetings whose delivery was interrupted after the answer come back as Home cards on launch (last 7 days). | **Yes** |
| 4 | Backend: `invitee_decision` + a separate `invitee_delivery_status` on each meeting (the organiser's `delivery_status` machine is untouched, IN-478 stays intact); `GET /meetings/{id}/invitees`, `POST …/invitees/decision`; held first send and invitee-only later send in `POST …/email`. CI runs `verify:invitee-prompt`, `verify:invitee-cards`, `verify:email-notice`. | No |

**Not in this release: the SharePoint permission hardening** (IN-91/IN-398,
branch `codex/sharepoint-permission-hardening`). IN-488 was built on top of
it and then replayed onto `main` without it (Joseph, 22 Sep: "ship 488
alone"). One test carries a comment to restore `user_email=` when the
hardening lands. Consequence to know: IN-488's "Email invitees" grants
invitees per-file SharePoint view access again, for the first time since
18 Aug, on a library that has not yet had its owner folders secured; the
grants are additive to the access the library already inherits.

  the app before the pass completes → the "Notes are ready but nothing was
